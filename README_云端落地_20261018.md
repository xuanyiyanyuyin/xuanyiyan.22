## 一、训练入口改了什么（train_v22_stage1.py，+56/−6）

| # | 改动 | 目的 |
|---|---|---|
| 1 | 前置 `from v22_vmf_modules import (...)` | 原版 import 写在 `class MasterGate` 之后，直接跑 NameError |
| 2 | `temps = master_gate(sub_losses.unsqueeze(0)).squeeze(0)` | vMF 版 forward 含 batch 维，未批输入返回 [1,5] 导致 `temps[1]` 越界 |
| 3 | `SEED` 环境变量 + torch/random/numpy 播种 | 原版无任何种子，无法做对照 |
| 4 | 进度条加 `acc_same={cos_val}({ok}/{total})` | 训练前向的逐位准确率（与 CE 同源） |
| 5 | 展示路径加 `同前向: CE=… acc=k/n` | 同一 logits 同时打印 CE 与逐位 acc（判定"收敛但评测低"用） |
| 6 | 新增 `_sv_rich_from(sv, ct, p3lf)`，展示/考试路径改用它 | **核心修复**：原版评测用裸 sv，训练用 sv_rich（含 abc_prime + 记忆 me 注入）⇒ 两条路径不同源 |
| 7 | `attr_a.squeeze(0)` 删掉（2 处） | attr_a 已是 2-D，squeeze 导致考试集/记忆验证崩溃 |
| 8 | `total_steps` 改为 `epochs × ceil(pairs/batch)` | 原为 `epochs×200` 占位（或我先前写的 epochs×pairs），相变永不触发 |
| 9 | `WIRE_DISABLE` 开关（`_NullWire`） | 干净对照：不构造组件、不消耗 RNG |
| 10 | wire 实例化（reg 权重走 `WIRE_REG` 环境变量，默认 0.005） | 10 个组件接线入口 |

## 二、组件库改了什么（v22_vmf_modules.py，+5/−4）

| # | 改动 | 原因 |
|---|---|---|
| 1 | `LocalCurvatureEstimator.estimate(): return curvature, self.threshold` | 原实现对 float 调 `.item()`，一旦接入必崩 |
| 2 | `KappaPhaseScheduler.get_temperature()` 加 `max(0.1, min(1.0, …))` | crystallize 分支 `progress>1` 时温度变负 |
| 3 | `LocalCurvatureEstimator.step_threshold` 加 clamp | `step>total` 时阈值变负，预警恒真/恒假 |
| 4 | `AdaptiveProbeSet`：新增 `refine_every`，`refine` 用它取模 | 原写死 `%1000`，短跑永不执行 |

## 三、接线层（v22_wire.py，新增 13.9 KB）

10 个组件逐项接入：κ 调度 / 竞争性结晶 / 覆盖熵 / Betti / PCA 曲率 / 多尺度曲率 / 动量交换池 / 自适应探针 / 因果探针 / SSOL+MI。
关键设计：
- 微头定义 = `explore.net[-1].weight` 的 256 行方向（与 `meta.kappa` 一一对应）；
- κ boost **默认关闭**（`WIRE_KBOOST=1` 才开），上限 κ≤6（避免逐维 sigmoid 饱和把 256 个门梯度清零）；
- 覆盖度：原生 `sims>0.5` 在 512 维不可达（实测最大余弦 0.117）⇒ 另算 top-5 密度熵 `coverage_topk`；
- Betti：累计 reorg 改每千步速率；
- 所有组件调用包 `_safe`，异常只记一次、不打断训练。

## 四、怎么复现

```bash
# 环境：AMD ROCm（本包在 /opt/robotwin-env 下跑通，torch 2.9.1+rocm7.2）
cd 远端原样
# 4 条数据、300 epoch、纯监控：
SEED=42 WIRE_REG=0 python train_v22_stage1.py --data v22_train_4.tsv --epochs 300 --display 100 --turbo
# 干净对照（不构造任何组件）：
SEED=42 WIRE_DISABLE=1 python train_v22_stage1.py --data v22_train_4.tsv --epochs 300 --display 100 --turbo
# 打开 κ 相变（真实训练时才建议）：
SEED=42 WIRE_KBOOST=1 WIRE_REG=0.0005 python train_v22_stage1.py --data <大语料> --epochs <N> --turbo
```

## 五、实测结论

**核心修复（sv_rich）前后对照，SEED=42、wire 开、4 对 300 epoch**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 训练 loss (E300) | 0.0037 | 0.0031 |
| 展示路径 ok | 1/7 | **7/7** |
| 展示同前向 CE | 2.67→**7.92** | 3.14→**0.0000** |
| 展示同前向 acc | 1/7 | **7/7** |
| 考试集 | 0/15 | 0/15 |
| 崩溃 | 0 | 0 |

⇒ 之前"loss 收敛但评测为 0"的矛盾 = **训练与评测两条路径不同源**，不是种子、不是度量 bug。
⇒ 考试集 0/15 属数据量问题（V22 文档自述需 5000~50000 对），4 对数据下正常。

**接线安全性**：clean control（A2）与监控臂（B2）loss 同量级（0.0022 vs 0.0030）、0 崩溃、0 组件失败。
